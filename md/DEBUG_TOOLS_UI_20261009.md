# 仮デバッグと優先UI修正の実装・検証

2026-10-09。開発担当。統括から受領したユーザー承認済み依頼「じゃあそれと優先修正事項を治して」に対応。

## 結果と操作

- エディタ実行、または専用 `Windows Development` プリセットの**debug出力**でF10を押す。開発環境の設定画面にも入口がある。既定OFF。開いている間はポーズし、F10/ESCで閉じる。
- パネルのON後だけ、HP無限・TP+100・全装備/全ステージ一時解放・道中からボス直行・合法なCOUNTER充填・個別一時リセットを使える。HP無限でも被弾反応は維持する。
- OFFは出撃・練習を終了し、開始前の状態と設定を復元してメインメニューへ戻る。効果を残したまま通常プレイに復帰する操作ではない。
- 通常debug出力、通常release出力、専用プリセットのrelease出力は、入口と各操作を拒否する。起動引数による解除処理は設けていない。

ビルド条件は `debug and (editor or counter_debug)`。`counter_debug` は専用プリセットだけに付与し、出力先は `export/development/counter-core-debug.exe`。通常応募プリセットには付けていない。[Godot公式のFeature tags](https://docs.godotengine.org/en/stable/tutorials/export/feature_tags.html)に沿って、エディタとexportの条件を分けている。コードやPCKを改変できる相手に対する保護まで保証する方式ではない。

## 保存と戦闘の境界

- ON中の通常保存・設定保存・削除を抑止し、進行/設定のスナップショットを復元する。ステージ番号とスコアは一時メモリに保持し、リトライを維持する。
- 練習の内側/外側でONにした場合の復元、練習退出、敗北、リトライ、OFF退出を検証した。デバッグ時のTIPS読込も一時状態を返す。
- ボス直行は道中の既存遷移を使い、旧敵・弾・捕獲弾・予約スポーンを清掃する。ボス中の再直行は拒否する。
- COUNTER充填はボス戦のCHARGING/READYだけ。ACTIVE/SPENTを解除せず、通常1戦1回のルールを維持する。
- キー割当中、F10を既存操作へ割り当てた状態、既存ポーズ、説明/確認画面、操作ロック、敗北/勝利中では入口を開けない。
- DEBUG表示は練習ヒント・警告帯と重ならない位置へ出す。

## 優先UI修正

1. 個別リセットを一時デバッグへ移し、全強化リセットの説明・完了通知にHP、パリィ、冷却、主兵装/捕獲威力、シールド固有範囲、フォーカス、COUNTER持続/威力を明示。通常の全セーブ初期化は確認付きの入口を維持し、デバッグON中は無効化。
2. ラボのCOUNTER持続欄を共通の倍率表示へ変更。支援/ファンネル/ミサイル10〜20秒、レーザー6〜12秒、5連鎖1.5〜3秒、巨大弾は画面外で終了する説明を添えた。戦闘の時間式は変更していない。
3. 画面サイズを実倍率の50/75/100/125%で表示し、既存の60%など独自値も選択中の値として残す。3比率とメニュー/ポーズで値を揃えた。
4. シールドTIPSに、カウンター/増幅は熱、吸収マトリクスは再展開時間で管理する例外を明示。
5. ONLYの有効表示を「選択したCOUNTER兵装のみ」へ修正。

描画で見つかったラボの旧「+50 TP（テスト用）」も、デバッグON中だけ表示・実行できるように制限した。通常版やOFF中に関数を直接呼んでもTPは増えない。

## 検証

保存先を分離した `.godot/implementation_check` でGodot 4.7.1を順番に実行。ゲーム/設定の保存先は `res://verification_save.cfg` / `res://verification_settings.cfg`。実ユーザーのセーブを試験対象にしていない。

| 確認 | 結果 |
| --- | --- |
| インポート | 終了コード0、パースエラーなし |
| debug_tools | 終了コード0/TEST_OK。保存バイト不変、状態復元、入力競合、HP反応、直行清掃、合法充填、旧TP制限を確認 |
| pause_settings / simulator_precision / campaign_combat | 3試験とも終了コード0/TEST_OK |
| 通常debug実exe | export/実行とも0。debug=true、editor=false、専用タグなし、拒否 |
| 通常release実exe | export/実行とも0。debug=false、editor=false、専用タグなし、拒否 |
| 専用debug実exe | export/実行とも0。debug=true、editor=false、専用タグあり、許可 |
| 専用release実exe | export/実行とも0。debug=false、editor=false、専用タグあり、拒否 |
| 描画 | 675/800/900×1200のデバッグOFF/ON、リセット通知、設定倍率、COUNTERラボ、練習HP∞を15枚確認 |

配布用exeはパス上書きの起動引数を拒否するため、検証コピーだけに確認シーンを組み込んで4条件をexportした。実際のdebug/releaseテンプレートで入口・操作・旧TPボタンの拒否を確認しており、エディタでPCKを読み込んだ結果をreleaseの証拠にはしていない。これらは検証専用exeで、遊ぶための完成配布物ではない。製品のmain_sceneはメインメニューのまま。

実操作での入力感、FPS、全ステージ通し、通常の全セーブ初期化の実削除は未確認。静的確認では既存の全初期化処理に旧 `savegame.cfg` を削除する箇所があり、現行 `SAVE_PATH` と不一致。この既存不具合の修正は別件として統括へ引き継ぐ。

## 作戦選択の配色接続

「画像・デザインの相談」でユーザーが「いい感じ」と承認し、開発への送信を許可した明るめの候補を適用した。対象は `game/core/stage_selection.gd` の配色・字体・ボタン状態だけ。進行・文言・配置・保存・戦闘ルールは変更していない。

基準ファイルの一致と `git apply --check` を確認し、既存の捕獲追撃/図鑑文言を保持して合流。反映後SHA-256は `134B3EB0731B73357B9F5004A7A0CBEC66DC867740F3CF1D60058745369830BE` で承認候補と完全一致する。

675/800/900×1200でNORMAL、未解放、HARD、左右移動、出撃の有効/無効/フォーカス、図鑑/TIPSの開閉を確認した。描画15枚と変更前675pxのHARD/TIPS比較2枚を保存。

配色・字体・ボタン状態は反映済み。ただし675pxで下部ボタンが左右4.5pxずつはみ出し、675/800pxのStage5 HARDでは長い難易度欄が詳細カードを広げる。狭幅TIPSも固定幅によるはみ出しが残る。変更前の描画でも再現する既存配置の問題であり、今回の配置維持という範囲には含めず、次のレイアウト修正として引き継ぐ。描画試験成功を、全比率の収まりに問題がない証拠として扱わない。
